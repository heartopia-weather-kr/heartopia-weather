# 두근두근타운 날씨 — 프로젝트 마스터플랜
최종 디자인 기준 v1.4 · 2026-11-18 · 기존 운영 코드/디자인 변경 금지

## 목적과 기준
- 운영: https://heartopia-weather-kr.github.io/heartopia-weather/
- 저장소: https://github.com/heartopia-weather-kr/heartopia-weather
- 현재 프로젝트 범위는 **날씨 사이트**. 예전 지도/도감 프로젝트와 혼동하지 않는다.
- 이 문서는 과거 대화의 확정 결정과 2026-11-18 운영 화면 캡처 검증 결과를 보존한다.
- **우선순위:** 사용자의 최신 명시적 승인 > 실제 운영 화면·현재 코드 > 이전 확정 대화 > 초기 구상·시안.
- 기존 사이트의 HTML/CSS/JS, 이미지, 수집기, 워크플로, 날씨 매핑을 승인 없이 수정하지 않는다. 문서 보관은 사이트 변경 승인이 아니다.

## 1. 확정된 디자인
- **Light 기본 스킨**, Midnight 선택 스킨. 두 스킨의 정보 구성과 배치 동일. 선택 상태 유지.
- **PC:** 상단 헤더·스킨 전환, 마지막 업데이트 표시, 2열 대시보드. 상단 왼쪽 현재 날씨 / 오른쪽 7일 예보, 하단 왼쪽 오늘 시간별 날씨 시계 / 오른쪽 업데이트 예정 카드, 하단 가로 계산기, 푸터.
- **모바일:** 헤더 → 마지막 업데이트 → 현재 날씨 → 시간별 날씨 시계 → 7일 예보 → 업데이트 예정 → 계산기 → 푸터의 세로 스크롤. 팝업은 모바일 폭에 맞춰 표시하고 내부 스크롤.
- 현재 날씨: 날짜, 현재/다음 예보 시간·아이콘·명칭, 변경/유지 표시, 오늘 변경 횟수, 풍경 배경.
- 날씨 시계: 12시 위, 오전/오후 전환, **실시간 전용**, 시간 클릭 예보 선택 제거, **중앙 시계바늘 제거**, 중앙 현재 날씨와 시간, 시간대별 날씨 아이콘과 강조 링. 과거 바늘 구상은 폐기.
- 7일 예보: **오늘 제외 다음 7일** 카드, 특수 날씨 강조, 선택 시 시간별 예보 팝업.
- 상세 예보 팝업: 날짜 이동, 변경 횟수·변동률, **기본형**(오전 06~11 / 오후 12~17 / 저녁 18~23 / 다음날 새벽 00~05의 시간별 목록), **묶어보기**(시간대별 선택), 닫기 버튼과 팝업 내부 스크롤. 모바일/PC 모두 유지.
- 계산기: 가로 카드의 아이콘+제목으로 별도 팝업 열기. 시작 시각 제외, 종료 시각 포함 규칙.
- 업데이트 예정 카드: **현재 운영 중인 보라색 공사 중 상점/셔터 그림 유지**. 11월 8일의 들판·달력 시안보다 현재 화면이 우선. 사용자 승인 없는 교체 금지.
- 색/아이콘: Light는 밝은 라벤더·흰 카드·파스텔 풍경과 컬러 아이콘. Midnight는 남색/보라 카드와 네온 아이콘. 임의로 새로운 스타일을 만들지 않는다.

## 2. 시간·데이터 원칙
- KST 기준 게임 날짜 **06:00~다음날 05:59**. 자정~05시는 전날 게임 날짜에 속함.
- 날짜가 바뀌면 이미 수집한 예보로 오늘/7일 표시를 전환하는 방향.
- 운영 화면에는 현재 날씨, 오늘 변경 횟수, 시계, 7일 예보, 시간별 예보, 계산기 등이 표시됨.
- 7일 화면과 데이터 저장 범위는 다르다. 이전 GitHub 코드 검토에서 9개 연속 게임 날짜 검증 로직 확인.
- 예보에 없는 날씨나 시간을 임의로 만들지 않는다.

## 3. 날씨 매핑·아이콘
- 초기 21종 디자인 참고표는 **최종 전체 매핑 수를 제한하는 명세가 아니다**.
- 이후 보통 눈, 뇌우 등 누락된 날씨를 보완하고 Light/Midnight 테마에 맞춰 전체 매핑을 정리했음.
- 이전 코드 검토 당시 날씨 카탈로그 **24개**, 기존 테스트/아이콘 매니페스트 일부는 **21개** 기준. 이는 추후 코드·테스트 대조 과제이지, 날씨 종류를 21개로 되돌리라는 뜻이 아님.
- 사용자가 승인한 현재 아이콘과 테마 표현을 보존하고, 차이 발생 시 개별 매핑 근거를 먼저 확인한다.
- 특수 날씨(무지개, 문레인보우, 유성우, 오로라 등)의 강조와 단계별 표현을 임의 단순화하지 않는다.

## 4. 범위 제외·보류
- **리딤코드 사이트 UI 디자인은 보류**. 수집기/JSON과 사이트 표시 UI는 별개이며, 추후 사용자 요청 때 재개.
- 지도·도감 통합 사이트 개발은 현재 범위가 아님.
- 새로운 레이아웃, 메뉴, 시계바늘, 스킨 기본값 변경, 날씨 재매핑은 사용자 명시적 승인 필요.

## 5. 디자인 검증 기록 (2026-11-18)
### 직접 확인한 원본
- `design-reference/dashboard-light.png`: PC Light 초기 대시보드 시안.
- `design-reference/dashboard-mobile.png`: 모바일 Light 초기 시안 및 팝업 예시.
- `design-reference/icons-light.png`: 초기 21종 Light 아이콘 참고.
- `design-reference/icons-midnight.png`: 초기 21종 Midnight 네온 아이콘 참고.
### 실제 운영 화면
- 사용자 제공 **모바일 Light 3장**, **모바일 Midnight 3장**, **모바일 상세 예보 5장**, **PC Light·Midnight·상세 팝업 4장**을 육안 비교.
- 확인: PC 2열 배치, 모바일 세로 순서, Light/Midnight 동일 구조, 현재 날씨·시계·7일 예보·계산기·업데이트 예정 카드, 기본형·묶어보기 및 내부 스크롤.
- 원본과 차이: 원본의 업데이트 예정 들판/달력 → 현재 보라색 셔터/상점; 시계 세부 요소와 배지/팝업 표현도 후속 승인·개발로 변화. **현재 운영 화면을 최신 디자인 보존 기준으로 채택**.
- 제한: 모든 날씨 종류·기기 해상도·브라우저·모든 버튼의 동작을 전수 검증한 것은 아님. 화면 캡처는 픽셀 단위 자동 비교가 아니라 육안 비교.

## 6. 기술 검증·후속 과제
- 이전 GitHub Actions 'Check weather UI' 실행(2026-11-16)에서 일부 테스트 실패. 날씨 카탈로그 24개와 21개 기준 테스트/매니페스트 불일치 등 원인 확인 필요.
- 현재 운영 화면이 표시된다는 사실과 테스트 전체 통과는 별개. **승인 없이 운영 코드·테스트를 고치지 않는다**.
- 후속 확인: 누락/추가 날씨 전 종류 Light/Midnight 아이콘 매핑, 특수 날씨 효과, 시간 경계 00/06시, 계산기와 팝업의 동작 회귀검증.
- 문서만 변경하는 작업은 사용자 승인에 따라 `docs/`에 한정한다.

## 7. 다음 대화 인수인계
1. 이 문서를 먼저 읽고 기존 디자인을 다시 결정하자고 묻지 말 것.
2. Light가 기본, Midnight가 선택이다.
3. 기존 화면이 최신 기준이며 11월 8일 이미지는 역사적 디자인 원본이다.
4. 날씨 매핑 24개와 테스트 21개 불일치를 우선 진단하되 승인 전에는 수정하지 말 것.
5. 리딤코드는 사용자 요청 시까지 보류.
6. 모든 GitHub 변경은 범위·파일·영향을 설명하고 사용자 승인 후 수행.

## 8. 변경 이력 관리 원칙
- 목적: 새로운 대화에서 최신 승인 결정을 잃거나 오래된 시안을 다시 적용하는 일을 방지.
- **기록 대상:** 신규 기능, 기능 동작/데이터 처리 변경, PC·모바일 레이아웃 또는 스킨 변경, 날씨 종류·아이콘 매핑 변경, 수집/자동화 방식 변경, 중요한 보류·재개·폐기 결정.
- **기록 생략 가능:** 의미 변화 없는 오타 수정, 단순 문구 교정, 기존 사양을 그대로 복구하는 사소한 버그 수정. 다만 사용자 판단에 따라 기록 가능.
- 기록 시 날짜(KST), 대상, 이전 상태, 변경 내용, 결정 이유, 승인 여부, 영향 파일/검증 결과를 남긴다. **승인 전 구상은 확정 변경으로 기록하지 않는다.**
- 과거 기록을 덮어쓰지 않고 새 항목을 추가한다. 상세 변경 내역은 [CHANGELOG.md](./CHANGELOG.md)에서 관리.
- 코드 변경과 문서 변경은 구분한다. 사용자 승인 없는 운영 코드 수정 금지.

## 9. 보류·범위 제외 관리 원칙
- **보류**는 아이디어·일부 구현이 있으나 다음 작업을 승인받지 않은 상태. 완료나 폐기와 다름.
- 보류 항목에는 현재 상태, 이미 결정된 방향, 미확정 부분, 재개 조건을 적는다. 세부 내역은 [PENDING.md](./PENDING.md)에서 관리.
- **범위 제외**는 현재 날씨 사이트 프로젝트에 포함하지 않는 작업이며, 자동으로 보류 기능처럼 재개하지 않는다.
- 보류 기능은 사용자가 재개를 요청하기 전까지 구현·배포하지 않는다.
