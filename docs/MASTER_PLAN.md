## 2. 변경해서는 안 되는 디자인 기준
### 2.1 테마와 레이아웃
- **Light 기본형 / Midnight 선택형** (11-08 14:53 사용자 명시; 실제 `assets/theme.js`의 기본값 `light`와 일치).
- **두 테마의 화면 구성은 동일**하게 유지하고 색감·아이콘 효과 등 테마 요소만 달리한다 (11-08 12:55).
- 11-08 사용자가 PC·모바일 시안을 승인(15:04, 15:08). PC 가로 대시보드, 모바일 세로 스크롤형을 기준으로 삼는다.

- 날씨 아이콘은 사용자가 확정한 원본을 기준으로 사용. 과거 대화에 **21종 아이콘**을 기준으로 구현한 기록이 있고, 이후 추가 매핑/아이콘이 논의·적용됨. **현재 최종 아이콘 수는 코드 재검증 전까지 21종으로 단정하지 않는다.**
- Midnight는 Light 아이콘의 형태를 유지하면서 네온/발광 효과를 적용하는 방향(11-08 16:06).
- 사이트 헤더, 오늘 날씨, 7일 예보, 시간별 날씨 시계, 계산기, 업데이트 예정 카드, 팝업 등 **기존 구성 보존**.

### 2.2 날씨 시계 — 초기 구상과 최종 변경을 혼동하지 말 것
- 시계는 **12시 방향이 위**인 표준 원형 배치.
- 11-08 20:00 사용자가 **A안: 원형 시계는 실시간 전용, 시간 클릭 제거**로 확정. 이전 '시간 클릭으로 예보 선택' 구상은 폐기된 구상임.
- 11-14 02:30 사용자가 **중앙 시계바늘 제거**를 결정. 과거 네온 바늘/삼각형 시안은 최종 디자인으로 간주하지 않음.
- 오전/오후 시계 전환과 새벽 시간 표시는 여러 차례 개선.
- 게임 날짜는 **KST 06:00~다음 날 05:59**. 자정~05시의 날씨는 이전 게임 날짜, 06시 이후는 새 게임 날짜 기준.
- 11-14 새벽 00~05시와 06시 이후를 **날짜 구분 링/색상으로 구분**하는 방식 승인·적용 확인.
- 11-14 오전 시계 12시 표기의 혼동을 피하도록 **오전 00시 / 오후 12시 표기** 방향 승인·적용 확인.
- 11-14 02:48 사용자 '아주 잘 적용됐네' 확인. 실제 현재 동작은 회귀검증 필요.
- 날씨 종류가 실제로 바뀌는 시간에만 변화 강조하는 원칙. 기존 UI의 표시/색상은 운영 코드 기준.

### 2.3 날씨 정보·계산기
- 화면에는 **7일 예보를 정확히 7개만 표시**(11-14 07:05, 07:24 재강조).
- KST 오전 06:00이 되면 기존 확보한 데이터로 오늘/7일 카드/변경 횟수를 **자동 전환**하는 방향 확정(11-14 06:38). GitHub Actions 실행 완료를 기다리는 방식이 아님.
- 데이터 확보 범위를 9일로 확대하는 논의·작업 기록이 있으나, **현재 수집·표시 구현 상태는 재검증 필요**.
- 예보에 없는 날씨를 임의로 만들어 보여주지 않는다. 데이터 오류·오래된 예보 경고가 중요.
- 7일 카드 선택 시 상세 시간별 예보 팝업. **기본형(길게 표시) / 묶어보기** 형태가 논의·구현됨. 현재 정확한 전환·저장 동작은 코드 확인.
- 계산기는 별도 팝업이며 계산기 아이콘과 제목을 누르는 구조. 시작 시각 제외~종료 시각 포함의 변경 계산 규칙(`README.md` 기준).
- 11-09 '날씨가 바뀌는 시간만 복사' 기능 A안 확정.
- 11-14 날씨 매핑 누락(보통 눈 등)과 추가 아이콘의 Light/Midnight 적용 요청 기록 존재. 현재 매핑 목록 재검증 필요.

- 공지 채널에는 리딤코드 외 다른 메시지도 있으므로 **리딤코드만 선별**해야 함(11-16 21:41).
- 중복 코드 통합, 한영 보상 정리, 만료 정보 처리 등의 개선 논의/작업 기록 존재. **모든 예외 케이스의 현재 통과 여부는 재검증 필요**.

- 여러 채널에서 모은 결과를 **사이트에서는 하나의 목록으로 표시**하기로 함.
- `index.html`을 확인했을 때 리딤코드 메뉴는 아직 없었음. **수집 기능과 사이트 UI는 별개**.

- 11-16 21:56부터 **기존 사이트에 적용할 디자인 시안** 요청.

## 6. 새 대화방 인수인계 프로토콜
새 대화가 시작되면 아래 순서로 진행한다.
1. **이 마스터플랜과 `HANDOFF.md`를 먼저 읽는다.**
2. 실제 GitHub `main`의 파일/최근 커밋/Actions를 **읽기 전용**으로 확인한다.
3. 디자인은 `design-reference/` 및 실제 PC·모바일 화면과 비교한다. 이미지가 없다면 '확인 못함'이라고 말한다.
4. 오래된 결정과 최신 결정이 충돌하면 **최신 사용자 확정**을 우선하고 근거를 남긴다.
5. 완료/미완료/보류를 구분하고, **바로 다음 한 단계**만 제안한다.
6. 사이트를 고치거나 배포하기 전 사용자 승인을 받는다.

## 12. 2026-11-23 내부 날씨 데이터 전환 및 운영 적용 확정

### 12.1 최신 사용자 확정 원칙 (이전 모래시계 구상 폐기)
- **캘린더는 절대 기준**: 날씨 유무와 관계없이 실제 KST 달력 날짜를 빠짐없이 생성한다. 날짜 누락, 월말/연말 건너뛰기, 시간·날짜 밀림은 허용하지 않는다.
- **데이터가 없는 연도·날짜·시간은 원인과 관계없이 `?`**: 기존의 '연도 변경 시 모래시계' 방안은 **폐기**. 정상 데이터가 있으면 정상 날씨를 표시한다.
- **차년도 데이터 선등록 허용**: 11~12월에 `data/weather-YYYY.json` 형태로 다음 연도 실제 데이터가 들어오면 해당 연도 1월 예보부터 그대로 사용한다. 데이터가 없는 연도의 날씨를 이전 연도에서 복사하거나 예측 생성하지 않는다.
- **366일 × 24시간 내부 원본 보존**: 원본의 2월 29일을 평년에는 사용하지 않으며, 3월 1일 이후를 한 칸씩 당기지 않는다. 윤년에는 2월 29일을 정상 조회한다. 원본 행 순번이 아닌 **연도 + 월·일 + 시각**으로 조회한다.
- **실제 변경만 집계**: 00/06/12/18시라고 무조건 변경 처리하지 않는다. 날씨가 실제로 달라진 시간만 변경으로 계산한다. 특수 날씨의 1/2/3 변형은 구분하고, 무지개 계열의 기존 정규화 규칙을 유지한다.
- **누락 구간 계산**: 앞뒤 데이터 중 하나라도 없으면 해당 구간의 변경 여부를 확정하지 않는다. 누락으로 인한 변경률을 임의로 0%라고 표시하지 않으며, 계산기에서 불완전한 구간을 거절한다.
- **집계 범위 구분**: 날짜 상세 팝업 상단의 '변경 N회 / 변동률 N%'는 **해당 날짜 24시간 전체** 집계이고, 하단 새벽/아침/오후/저녁의 '변경 N회'는 **각 6시간 구간** 집계다. 두 숫자가 다른 것은 정상. 전체 변경 수는 네 시간대 변경 수의 합과 일치해야 한다.
- **디자인 보존**: Light 기본, Midnight 선택, 기존 모바일/PC 카드, 날씨 아이콘, 원형 시계, 리딤코드 아이콘과 상세 팝업 스타일 유지. 사용자가 2026-11-23 모바일 스크린샷으로 라이트·Midnight 및 오전·오후 시계, 묶어보기, 특수 날씨 표시를 확인했다.
