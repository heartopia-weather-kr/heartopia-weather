## 1. 확정된 디자인
- **Light 기본 스킨**, Midnight 선택 스킨. 두 스킨의 정보 구성과 배치 동일. 선택 상태 유지.
- **PC:** 상단 헤더·스킨 전환, 마지막 업데이트 표시, 2열 대시보드. 상단 왼쪽 현재 날씨 / 오른쪽 7일 예보, 하단 왼쪽 오늘 시간별 날씨 시계 / 오른쪽 업데이트 예정 카드, 하단 가로 계산기, 푸터.
- **모바일:** 헤더 → 마지막 업데이트 → 현재 날씨 → 시간별 날씨 시계 → 7일 예보 → 업데이트 예정 → 계산기 → 푸터의 세로 스크롤. 팝업은 모바일 폭에 맞춰 표시하고 내부 스크롤.
- 현재 날씨: 날짜, 현재/다음 예보 시간·아이콘·명칭, 변경/유지 표시, 오늘 변경 횟수, 풍경 배경.
- 날씨 시계: 12시 위, 오전/오후 전환, **실시간 전용**, 시간 클릭 예보 선택 제거, **중앙 시계바늘 제거**, 중앙 현재 날씨와 시간, 시간대별 날씨 아이콘과 강조 링. 과거 바늘 구상은 폐기.
- 7일 예보: **오늘 제외 다음 7일** 카드, 특수 날씨 강조, 선택 시 시간별 예보 팝업.
- 상세 예보 팝업: 날짜 이동, 변경 횟수·변동률, **기본형**(당일 새벽 00~05 / 오전 06~11 / 오후 12~17 / 저녁 18~23의 시간별 목록), **묶어보기**(시간대별 선택), 닫기 버튼과 팝업 내부 스크롤. 모바일/PC 모두 유지.
- 계산기: 가로 카드의 아이콘+제목으로 별도 팝업 열기. 시작 시각 제외, 종료 시각 포함 규칙.
- 업데이트 예정 카드: **현재 운영 중인 보라색 공사 중 상점/셔터 그림 유지**. 11월 8일의 들판·달력 시안보다 현재 화면이 우선. 사용자 승인 없는 교체 금지.
- 색/아이콘: Light는 밝은 라벤더·흰 카드·파스텔 풍경과 컬러 아이콘. Midnight는 남색/보라 카드와 네온 아이콘. 임의로 새로운 스타일을 만들지 않는다.

## 2. 시간·데이터 원칙
- **2026-11-21 확정:** KST 기준 달력 날짜 **00:00~23:59**(표시 시간 00:00~23:00). 00~05시 예보는 해당 날짜에 포함하며, 과거 06~다음날 05시 게임 날짜 묶음은 폐기(PR #18).
- 날짜가 바뀌면 이미 수집한 예보로 오늘/7일 표시를 전환하는 방향.
- 운영 화면에는 현재 날씨, 오늘 변경 횟수, 시계, 7일 예보, 시간별 예보, 계산기 등이 표시됨.
- 7일 화면과 데이터 저장 범위는 다르다. 수집·검증은 오늘부터 9개 연속 **달력 날짜**를 대상으로 하며, 화면의 주간 카드는 오늘을 제외한 다음 7일을 표시한다.
- 예보에 없는 날씨나 시간을 임의로 만들지 않는다.

## 3. 날씨 매핑·아이콘
- 초기 21종 디자인 참고표는 **최종 전체 매핑 수를 제한하는 명세가 아니다**.
- 이후 보통 눈, 뇌우 등 누락된 날씨를 보완하고 Light/Midnight 테마에 맞춰 전체 매핑을 정리했음.
- 이전 코드 검토 당시 날씨 카탈로그 **24개**, 기존 테스트/아이콘 매니페스트 일부는 **21개** 기준. 이는 추후 코드·테스트 대조 과제이지, 날씨 종류를 21개로 되돌리라는 뜻이 아님.
- 사용자가 승인한 현재 아이콘과 테마 표현을 보존하고, 차이 발생 시 개별 매핑 근거를 먼저 확인한다.
- 특수 날씨(무지개, 문레인보우, 유성우, 오로라 등)의 강조와 단계별 표현을 임의 단순화하지 않는다.

## 8. 변경 이력 관리 원칙
- 목적: 새로운 대화에서 최신 승인 결정을 잃거나 오래된 시안을 다시 적용하는 일을 방지.
- **기록 대상:** 신규 기능, 기능 동작/데이터 처리 변경, PC·모바일 레이아웃 또는 스킨 변경, 날씨 종류·아이콘 매핑 변경, 수집/자동화 방식 변경, 중요한 보류·재개·폐기 결정.

- 기록 시 날짜(KST), 대상, 이전 상태, 변경 내용, 결정 이유, 승인 여부, 영향 파일/검증 결과를 남긴다. **승인 전 구상은 확정 변경으로 기록하지 않는다.**
- 과거 기록을 덮어쓰지 않고 새 항목을 추가한다. 상세 변경 내역은 [CHANGELOG.md](./CHANGELOG.md)에서 관리.
- 코드 변경과 문서 변경은 구분한다. 사용자 승인 없는 운영 코드 수정 금지.

## 9. 보류·범위 제외 관리 원칙
- **보류**는 아이디어·일부 구현이 있으나 다음 작업을 승인받지 않은 상태. 완료나 폐기와 다름.
- 보류 항목에는 현재 상태, 이미 결정된 방향, 미확정 부분, 재개 조건을 적는다. 세부 내역은 [PENDING.md](./PENDING.md)에서 관리.
- **범위 제외**는 현재 날씨 사이트 프로젝트에 포함하지 않는 작업이며, 자동으로 보류 기능처럼 재개하지 않는다.
- 보류 기능은 사용자가 재개를 요청하기 전까지 구현·배포하지 않는다.

## 10. 리딤코드 기능 현황 (2026-11-19, 보류 해제·구현 반영)
- **범위:** 날씨 사이트 헤더의 리딤코드 기능. 기존 날씨 레이아웃·날씨 계산·매핑과 분리하여 운영.
- **승인 디자인:** 간결한 보라색 리본 쿠폰 SVG(C안), 별은 중앙 배치. PC에서는 아이콘과 '리딤코드' 라벨, 모바일에서는 공간을 고려해 아이콘 위주. Light/Midnight 테마 변수 사용. PC·모바일 사용자 제공 화면을 검토하고 현재 배치를 승인함(PR #14, #15).
- **사용자 기능:** 팝업에서 사용 가능 코드와 만료 코드 구분, 만료 코드는 접기/펼치기, 코드 복사 및 결과 피드백, 보상 표시, 새 코드 NEW 배지와 헤더 빨간 알림 점. 새 코드 확인 상태는 브라우저 localStorage에 저장. 만료 시각 확인 가능한 미열람 활성 코드에 대해 빨간 점 표시.
- **만료 표시:** 72시간 이내 만료 임박 안내, 24시간 이상 남았을 때 일 단위, 24시간 미만 시간/분, 1시간 미만 분/초 단위 표시. 만료 시 만료 목록으로 이동. 만료일 미확인 항목은 별도 안내와 함께 활성 목록에 표시.
- **자동 등록:** `redeem_collector.py`가 Discord 집계 채널의 전달된 공지에서 코드를 추출하여 `redeem-codes.json` 갱신. GitHub Actions `.github/workflows/update-redeem.yml` 스케줄 유지. 자동 수집기 내부에서도 영문 대소문자를 무시해 동일 코드 병합.
- **수동 등록:** `manual-redeem-codes.json`을 GitHub에서 직접 편집하거나 공식 게시물 스크린샷을 제공해 검토·승인 후 등록. GitHub 메인 브랜치에 커밋하면 별도 운영자 승인 단계 없이 GitHub Pages 배포 후 공개. 모바일 편집 안내: `docs/MANUAL_REDEEM_GUIDE.md`.
- **통합·중복 제거:** 사이트의 `assets/redeem-ui.js`가 두 JSON 파일을 읽고 코드 앞뒤 공백 제거·대소문자 무시를 기준으로 하나만 표시. 자동/수동 중복 시 수동 레코드 우선, 특별 코드에 '🎁 특별' 배지 표시. 한쪽 로드 실패 시 다른 쪽의 정상 데이터는 유지·표시하며 일부 오류 안내. 수집기는 수동 파일을 덮어쓰지 않음.
- **수동 코드 최초 등록:** `letsgoall100` (소원별 ×10, 무지개 꽃다발 ×1, 깜짝 가챠 ×2; 2027-01-01 00:59 KST 만료). 사용자 제공 공식 게시물 스크린샷에 근거하여 수동 파일에 기록. 게시물 원문 URL은 미확인 상태.
- **관련 반영:** PR #14 (리딤코드 팝업·기본 기능), PR #15 (리본 쿠폰 아이콘), PR #16 (수동 파일·중복 제거·특별 배지·모바일 등록 안내). PR #16은 2026-11-19 메인 브랜치 병합 확인.
